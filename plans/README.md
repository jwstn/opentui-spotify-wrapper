# Plans

One markdown file per multi-commit feature or larger redesign, written *before*
the work starts. The aim is to capture **intent + design + open questions** so
any implementer (human or agent) can pick the work up cold.

## Format

Each plan should cover:

- **Why** — the user-facing problem or feature gap it addresses.
- **What we'd ship** — bullet-level description of the user-visible end state.
- **API / architecture mapping** — concrete services, atoms, commands, types.
- **Open questions** — design choices that aren't decided yet.
- **Out of scope (for v1)** — what we're explicitly *not* doing first time round.
- **Status** — `Not started` / `In progress` / `Shipped — see <commit/PR>`.

When a plan ships, leave the file in place and update the **Status** line so we
can read the history.
